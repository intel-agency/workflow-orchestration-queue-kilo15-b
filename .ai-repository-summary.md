# AI Repository Summary: workflow-orchestration-queue-kilo15-b

> This document provides a concise overview for AI coding agents working on this repository.

## Project Overview

**Repository:** `intel-agency/workflow-orchestration-queue-kilo15-b`
**Type:** Python async orchestration platform
**Purpose:** Headless agentic orchestration that transforms GitHub Issues into AI-executed tasks

## Technology Stack

| Layer | Technology |
|-------|------------|
| Language | Python 3.12+ |
| Web Framework | FastAPI (async) |
| HTTP Client | httpx (async with connection pooling) |
| Data Validation | Pydantic v2 |
| Package Manager | uv (Rust-based) |
| Testing | pytest + pytest-asyncio |
| Linting | ruff |
| Type Checking | mypy |

## Architecture: Four Pillars

```
┌─────────────────────────────────────────────────────────────────┐
│  THE EAR (Notifier)    │  FastAPI webhook receiver              │
│                        │  Validates HMAC signatures             │
├─────────────────────────────────────────────────────────────────┤
│  THE STATE (Queue)     │  GitHub Issues as persistence          │
│                        │  Labels = status, Comments = logs      │
├─────────────────────────────────────────────────────────────────┤
│  THE BRAIN (Sentinel)  │  Async polling service                 │
│                        │  Distributed locking via assignment    │
├─────────────────────────────────────────────────────────────────┤
│  THE HANDS (Worker)    │  DevContainer + opencode CLI           │
│                        │  Isolated execution environment         │
└─────────────────────────────────────────────────────────────────┘
```

## Data Models

### WorkItem

```python
class WorkItem(BaseModel):
    id: str | int
    issue_number: int
    source_url: str
    context_body: str
    target_repo_slug: str
    task_type: TaskType
    status: WorkItemStatus
    node_id: str | None = None
    metadata: dict[str, Any] = {}
```

### TaskType Enum

- `PLAN` - Planning/architecture tasks
- `IMPLEMENT` - Implementation tasks

### WorkItemStatus Enum

Maps to GitHub labels:
- `agent:queued`
- `agent:in-progress`
- `agent:success`
- `agent:error`
- `agent:infra-failure`
- `agent:stalled-budget`

## Security Notes

1. **Never commit secrets** - Use `.env` file (gitignored)
2. **All outputs are scrubbed** - `scrub_secrets()` removes tokens before posting to GitHub
3. **Webhook validation** - HMAC SHA256 signature required on all webhook requests
4. **Distributed locking** - Uses assign-then-verify pattern with bot account

## Code Style

- **Line length:** 100 characters
- **Formatting:** ruff format (double quotes, space indent)
- **Imports:** isort via ruff
- **Type hints:** Required for all function signatures
- **Docstrings:** Required for public functions/classes

## Testing Strategy

- **Unit tests:** All models and utility functions
- **Async tests:** Use pytest-asyncio with `asyncio_mode = "auto"`
- **Fixtures:** Shared fixtures in `tests/conftest.py`
- **Coverage target:** 80%+

## Important Constraints

1. **GitHub Actions SHA pinning:** All workflow actions MUST use commit SHA, not version tags
2. **No curl in Docker healthchecks:** Use Python stdlib instead
3. **uv pip install order:** `COPY src/` before `uv pip install -e .`
4. **Label creation:** The `orchestration:plan-approved` label must be created during setup
